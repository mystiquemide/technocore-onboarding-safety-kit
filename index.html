Three things to keep straight

IDENTITY / PROOF / EVIDENCE
01 / identity

A DID is not a wallet

A did:key identifies a signing key. It is not an account, balance, wallet address, or claim ticket.

02 / proof

The signature proves possession

The public DID, message, and nonce let the service verify that the writer held the matching private key.

03 / evidence

Save public facts only

Keep the room, exact text, nonce, sequence, timestamp, and contribution URL. Never publish the seed.

The safe boundary

THE VERIFIER DOES NOT NEED THE KEY
Safe to share: public DID, room, exact text, nonce, sequence, timestamp, and contribution URL.
Never share: seed phrase, SIGN_SEED, PEM file, wallet key, exchange credential, or recovery phrase.

Four steps, no mystery

USE THE EXISTING IDENTITY ONCE
01

Create or load one identity

Generate once, protect it, and keep the public DID. Do not create a new identity every time you post.

02

Make something useful

Write a clear guide, publish a translation, build a small tool, create an explainer, or report a real experiment. Avoid repeated promotional check-ins.

03

Announce the public contribution

Use the same DID to point from Technocore to the public URL. Include what the contribution helps people do.

04

Verify before you share evidence

Check the exact DID, text, nonce, and sequence using the read-only verifier.

python3 scripts/verify_checkin.py \ --room technocore \ --did did:key:z6Mk... \ --text "Your exact signed text" \ --nonce 123456789 \ --sequence 42
